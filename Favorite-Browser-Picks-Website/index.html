What this is

This repo holds two separate things and I keep them separate on this page too. The first is a short pick list: the browsers I point people to, as links. The second is code, a Tampermonkey userscript I wrote that sends DuckDuckGo searches to StartPage.

My README gives the picks as links and nothing more. It does not write out reasons for either browser, and I am not going to invent reasons here to fill the page. The order is the statement: Opera GX first, Opera Air second. That order is the ranking, and I am leaving it exactly as I wrote it.

The userscript is the part I can describe in detail, because I can point to what it does line by line. It reads one query value and changes one address. Everything else on this page is that script and its limits.

In the same repo: the script

startpage_redirection.js, a Tampermonkey userscript at version 0.2. On a DuckDuckGo search page it reads the q value and sends the browser to https://www.startpage.com/do/search?q= plus the encoded query. A page with no query is left alone. StartPage is on neither match pattern, so there is no loop.

It runs at document start on purpose. The redirect has to fire before DuckDuckGo renders, or I see the engine I asked not to use and the browser does the work twice.

The query is decoded by URLSearchParams and has to be encoded again on the way out. Without that step, a query holding an ampersand or a hash would break out of the q value and change what the StartPage address means. A test with a&b#c stayed inside one parameter.

The match fix

The script used to carry only *://duckduckgo.com/*. In Tampermonkey rules that matches the bare host only, so it missed www.duckduckgo.com and html.duckduckgo.com, the hosts people actually land on. A second pattern, *://*.duckduckgo.com/*, now sits next to the first. Neither pattern covers the other, so both stay.

Honest note

I checked the script with a Node harness that stubs window.location. A query page redirected to the right StartPage search, and a page with no query kept its address. The match pattern fix is a reading of Tampermonkey match rules, not a browser run. I did not load the script in a real browser with Tampermonkey in that pass, and the README says so.
